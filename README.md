# NEK

Учебное мобильное приложение МТИ для онлайн-записи в студию лазерной эпиляции. Проект основан на сценариях iOS-версии Epil TJ. В NEK перенесены компоненты оформления SwiftUI и правило пересечения визитов. Каталог, аккаунты и локальный сервер подготовлены для защиты проекта.

Клиент выбирает услугу, специалиста, дату и свободное время. После подтверждения запись появляется в «Моих визитах». Администратор открывает календарь и видит записи выбранного дня. При двух запросах на одно время сервер подтверждает одну запись и возвращает второму клиенту HTTP 409.

## Требования

- macOS, Xcode 16 или новее, симулятор iPhone с iOS 17 или новее.
- Docker Desktop или другой движок Docker с Docker Compose.
- Node.js 24, если запускать серверные тесты вне контейнера.

## Запуск

```sh
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8080/api/health
open NEK.xcodeproj
```

В Xcode выберите схему **NEK**, любой симулятор iPhone и нажмите **Run**. Приложение подключается к API на `127.0.0.1:8080`. Docker Compose запускает сервер, а Xcode запускает нативный клиент.

| Роль | Логин | Пароль |
| --- | --- | --- |
| Клиент | `client` | `client-demo` |
| Администратор | `admin` | `admin-demo` |
| Второй клиент | `guest` | `guest-demo` |

На экране входа кнопки «Клиент» и «Администратор» выполняют вход с демонстрационными учётными данными через сервер. Начните с завтрашнего дня, чтобы в интерфейсе были все рабочие окна. После записи перейдите в «Мои визиты». Выйдите, войдите администратором и выберите ту же дату. Все даты и время интерфейса относятся к часовому поясу Душанбе.

Для остановки оставьте данные командой `docker compose down`. Команда `docker compose down -v` удаляет локальную учебную базу.

## Тесты

```sh
npm test
docker compose config -q
xcodebuild -project NEK.xcodeproj -scheme NEK -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath .build \
  CODE_SIGNING_ALLOWED=NO build
```

Серверные тесты выполняют запросы к REST-обработчику с SQLite. Они проверяют авторизацию, правила доступа, отображение созданной записи, параллельное бронирование, смежные интервалы и сохранение после открытия файла базы заново.
